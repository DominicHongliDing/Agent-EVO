# Agent EVO · 产品设计

EVO 面向已有问答和多轮 Agent 的小团队，支持准备测试要求、审核回答、确认问题和复测改动。产品目标是让产品、业务与研发使用同一份输入、预期和证据，减少反复解释问题与重建测试条件的成本。

## 用户任务与优先流程

| 使用者 | 需要完成的任务 | 对应设计 |
| --- | --- | --- |
| 产品负责人 | 确定评测目的与改进优先级 | 按检查质量、比较版本或验证问题组织任务 |
| 业务审核者 | 确认预期、核对评审理由 | 问答、标准、参考材料与引文一起查看 |
| 开发者 | 复现、修复并提交新结果 | 连接器、执行记录与可比版本条件 |

首轮使用验证聚焦“导入一条对话、确认问题、保存复测要求”。已有回答可先审核；需要重复执行时再配置 Agent 连接，应用保留在原有电脑、内网或云服务中。

表格与人工复核适合问题较少的阶段。EVO 优先处理多轮对话、反复修改和多人审核中的材料追溯与复测衔接，外部团队的使用价值仍待验证。

## 评测要求怎样形成

先写清本轮要做的决定，再从用户任务定义正确表现、边界与反例。测试题可以由 AI 草拟，业务人员确认代表性、参考资料和验收要求，再保存题库版本。

[核心案例](cases/correction-review.md)的要求是：用户明确更正病程并要求总结后，回答应采用新内容、概括已知事实、单列未知项。审核围绕原文和任务完成展开，医学结论不作为模型自行补写的参考答案。

## 能力与判断分工

| 工作 | 使用方式 | 人工责任 |
| --- | --- | --- |
| 准备测试集 | 模型草拟、独立检查典型与边界场景 | 确认预期、覆盖与参考依据 |
| 检查格式字段 | 规则校验 | 定义规则及适用范围 |
| 评价语义与多轮表现 | 模型给理由与引文 | 确认、修正或标记无法判断 |
| 整理报告 | 汇总已保存结果 | 决定优先级、责任和发布安排 |

当前模型服务主要为百炼，其他厂商接口尚不能直接替换。AI 调用集中在需要生成或语义判断的步骤，浏览历史与人工审核可独立进行。

## 从结论逐层查看依据

审核页同时呈现输入、实际回答、预期与评审理由。处理时间线默认展示业务动作、结果和状态；进入步骤后查看输入输出，再展开原始事件与参数。未知事件保留原始说明，已观察的问题和可能原因分别显示。

人工修正保留原判断及修改理由。确认的问题可归组、安排改进并保存回归场景。修复后记录程序、模型、提示词、上下文配置和评审规则；条件变化时明确比较范围，未复测的问题保留待验证状态。

## 异常与接手人

| 情况 | 系统动作与用户看到的内容 | 谁继续处理 |
| --- | --- | --- |
| 缺前文或参考资料 | 标记材料不足，保留可判断范围 | 审核者补材料或保留待确认 |
| 未上报执行步骤 | 显示现有问答与记录范围 | 开发者按需补充日志 |
| 模型评审失败 | 保留材料与已有意见，显示失败入口 | 审核者重试或人工审核 |
| 人与模型意见不同 | 保存原判断、修正意见与理由 | 业务人员确认，开发配合核查 |
| 版本条件不同 | 显示差异与可比范围 | 产品与开发确认比较方式 |
| 尚无修复后运行 | 保持待复测 | 开发提交新记录，审核者验证 |

平台记录审核与发布依据，发布由团队决定；业务系统的线上修改由研发负责。Clinical 材料用于验证信息处理行为，医学有效性另行专业评阅。

## 验收与试用计划

| 层面 | 检查任务 | 收集记录 |
| --- | --- | --- |
| 功能 | 导入、审核、修正、保存回归场景 | 完成与失败状态，材料是否保留 |
| 判断质量 | 对照有明确要求的对话检查理由 | 引文支持、人工分歧、无法判断项 |
| 可理解性 | 首次使用者找到问题与依据 | 卡点、耗时、需要协助的步骤 |
| 改进价值 | 完成一次固定条件的修复后复测 | 对实际改动有帮助的结论与无用报告 |

同时观察题目重写比例、引文核对便利性、连接配置成本与全过程用时。上述为下一轮验证计划，尚无外部试用结果；现有自动化测试覆盖相应软件行为。

## 当前实现、来源与迭代

已有回答导入、题库草拟与审核、Agent 连接、评审复核、问题归组、版本比较、回归任务与报告导出。HTTP / Python 是主要接入方式，Dify、LangChain、LangGraph 提供需调整的样例。[本地指南](local-setup.md)提供安装与模型配置。

需求来自我迭代 UniHR 和 Clinical Agent 时保存问题、比较修改的需要。我负责流程、审核界面、问题跟进和验收设计，并借助 AI 编程工具实现平台。

下一步先验证首次使用的最短流程，再调整入口、说明和评审方式；更多平台适配与复杂团队权限依据实际需求扩展。
