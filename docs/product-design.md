# EVO 的产品设计：评完之后，团队怎样继续改

[返回项目](../README.md) · [核心案例：从更正失败到复测要求](cases/correction-review.md) · [运行与接入](local-setup.md)

## 问题从哪里来

做 UniHR 和 Clinical Agent 时，我遇到过文件遗漏、回答未采用新信息、引用不能支持结论等问题。修改提示词、模型或流程后，如果没有保存原输入、要求和运行条件，就很难判断改善了哪里。

EVO 因此从自己的项目需要开始：让产品、业务和开发同事能够说明问题、确认预期，修复后再测一次。适合更多团队的程度，还需要外部使用验证。

## 首先服务谁

当前聚焦已有问答和多轮 Agent 的小团队。产品负责人决定先修什么；业务审核者判断是否符合实际工作；开发者负责复现、修复与接入。三类人需要的是可以共同核对的材料，而不是各自维护一份含义不同的结论。

| 用户任务 | EVO 提供的支持 | 用户完成后的结果 |
|---|---|---|
| 检查已有回答 | 导入记录，对照要求逐条审核 | 有原文与理由的问题记录 |
| 准备可重复测试的问题 | AI 起草场景，人工修改确认 | 有预期和版本的测试集 |
| 比较改动 | 在可比条件下查看版本结果 | 明确改善、退步与待确认项 |
| 验证已知错误 | 保存回归场景，修复后重新运行 | 以新记录判断是否达到原要求 |

## 为什么需要一个工作台

问题很少时，表格与人工复核就可以开始。EVO 需要证明的价值，是在多轮对话、反复修改和多人审核时，减少整理原文、追溯判断和重建复测条件的成本。

因此首先保留已有回答入口。接入 Agent 需要研发配合，业务人员可以先审核手头的记录；需要重复执行时再配置连接器。Agent 继续留在原来的环境，不必先迁移应用。

首轮使用验证聚焦“导入一条对话、确认问题、保存复测要求”。平台虽然已有更多功能，首次体验不要求用户先完成整套配置。

## 核心案例：更正信息后，没有完成总结

[这条 Clinical 记录](cases/correction-review.md)中，用户把“两周”改成“三天”，Agent 再次返回信息不足提示，没有按要求总结。EVO 围绕它呈现两轮原文、预期、实际回答和处理记录。

案例说明怎样写准确的评审意见、为什么不能仅凭回答推断根因、怎样逐层查看执行依据，以及没有复测结果时怎样保持待验证状态。它也给平台自身提供验收任务：首次使用者能否独立找到证据并保存后续要求。

## AI 能力与人工判断

| 能力 | 对应需要 | 人工责任 |
|---|---|---|
| 测试题草拟与检查 | 从产品说明展开典型、缺失与边界场景 | 确认代表性、业务预期和参考依据 |
| 模型辅助评审 | 阅读多轮内容，给出具体理由和引文 | 确认或修正判断，不让模型自行补业务事实 |
| 报告整理 | 将已保存结果组织成便于讨论的问题 | 决定优先级、责任和下一步 |
| 规则检查与版本记录 | 校验明确格式，保存可比条件 | 确定规则与本轮要回答的问题 |

不要求所有检查都调用模型。确定性格式使用规则；语义判断由模型辅助；有争议或高影响的判断交人工。当前模型服务主要为百炼，其他厂商尚不能直接替换。

## 异常、分歧与下一步

没有参考资料时，说明哪些事实无法判断；缺少前文时不作完整的上下文评价；未上报执行步骤时不推断某工具出错。评审调用失败保留材料，让审核者重试或继续人工审核。

人工修改意见需要留存原判断和理由。确认的问题可以归组、安排改进与保存回归场景；题目、参考材料或评分标准变了，需要先核对可比性。没有修复后运行，问题保持待复测。

平台不根据一个总分自动批准发布，也不自动修改线上业务系统。Clinical 材料用于检查信息处理行为，医学有效性需要另行专业验证。

## 怎样验收 EVO 自己

| 层面 | 检查任务 | 可以收集什么 |
|---|---|---|
| 功能 | 导入、审核、修正意见、保存回归场景 | 完成与失败记录，材料和状态是否保留 |
| 判断质量 | 用有明确要求的对话核对评审理由 | 原文支持情况、人工分歧与无法判断项 |
| 可理解性 | 首次使用者找到问题和对应依据 | 卡点、耗时、需要协助的步骤 |
| 改进价值 | 修复后完成一次可比复测 | 哪些结论支持实际改动，哪些报告用不上 |

试用时同时观察题目有多少需要重写、引文是否方便核对、连接与配置花了多少时间。上述为下一轮验证计划，尚无外部使用结果。现有软件测试只能覆盖相应功能行为。

## 当前阶段与迭代顺序

已有回答导入、题库草拟与审核、连接器、评审复核、问题归组、版本比较、回归任务及报告导出；公开案例保留了原失败。[本地指南](local-setup.md)提供运行与配置方法。

下一步先验证首次使用者能否完成最短流程，再依据反馈改入口、说明和评审方式。更多平台适配、复杂团队权限和更多 Agent 形态，需要在核心任务有效之后按需求扩展。Dify、LangChain、LangGraph 目前提供接入样例，不能据此承诺覆盖所有应用。

我负责定义评测流程、审核体验、问题跟进与验收要求，并借助 AI 编程工具实现平台。当前没有把平台接入量、真实用户规模或业务改善写成已经取得的成果。
